# P1a Requirements v1.0

## 1. 功能要求

**REQ-01 构建**：使用用户现有且唯一的 `Projects/RTnode.uvprojx`，目标 STM32F103ZET6、ARM Compiler 5.06u7，记录实际 target、绝对/相对路径、编译宏 `STM32F103xE`、HAL/CMSIS include 路径、Startup 与 system 文件唯一性、Flash/SRAM 设置；产出可重复 Build Log、AXF/HEX（或解释 Hex 未开启）、MAP 及资源统计。不能无证据声称构建通过。

**REQ-02 启动**：建立从复位进入 main 后的最早可行软件安全关断、`HAL_Init`、NVIC/时钟配置、失败时继续禁止输出的顺序。P1a 不启动 Scheduler。禁止初始化完成就自动输出 PWM。

**REQ-03 旧中断隔离**：清除 P1a 不需要的 `protocol_transport.h`、`ProtocolTransport_UartIrqHandler()` 等旧 USART2 编译依赖；保留与 Startup 一致的中断向量和必要异常路径。

**REQ-04 目标引脚**：TIM3_CH1=PC6、TIM3_CH2=PC7、TIM3 full remap，绝不将 PA6/PA7 当作舵机输出。初始化、Enable、Apply、Disable、ForceSafe、异常路径全面迁移。

**REQ-05 PWM**：TIM3 50 Hz、计数分辨率 1 µs，推荐 PWM1 active-high、CCR preload 和 ARR preload；必须实际核对 HAL 的定时器初始化及 update event 行为。两个通道的比较寄存器更新不得跨越同一次周期产生前后不一致的控制帧。

**REQ-06 范围**：Pan 1000–2000 µs、Tilt 1200–1600 µs、中位 1500 µs；沿用旧模块绝对目标脉宽 `ActuatorCommand` 风格，不引入旧增量式图像误差控制。

**REQ-07 安全**：上电、初始化、未授权、失败、正常禁用、紧急关闭、故障后始终禁止命令 PWM，直至满足条件；故障锁存不得通过普通 `Enable()` 清除。P1a 可采取“故障复位才能恢复”作为简单保守策略。安全关闭应先操作硬件，再考虑诊断更新。

**REQ-08 恢复**：正常 `Disable()` 可在明确的新授权后重新 `Enable()`，必须从双通道中位开始，不能恢复禁用前旧命令；紧急故障锁存后不得通过相同途径使能。

**REQ-09 可观测**：提供初始化、enabled、fault-latched、最后脉宽、计数器的可信只读快照；明确异常和中断并发下快照的一致性限制。

**REQ-10 测试**：提供不依赖 FreeRTOS 的最小、安全受控测试程序或编译时开关，开关默认关闭，不在上电后自行扫动。用户用逻辑分析仪先测试无负载，再受限机械测试，保留波形原始文件和设置。

**REQ-11 可追溯复用**：逐项记录从旧库复制/参考的文件、旧 commit、相对于旧代码的硬件/行为修改、静态与实机回归范围。不修改旧仓库。

## 2. 已批准约束

- 单一 Keil 工程；旧 actuator API 局部复用；PC6/PC7 安全初始化；默认禁止输出；明确的故障锁存。用户已确认本地工程存在且配置正确，本阶段不以“未上传工程文件”为故障前提。
- ControlTask 是**未来 P1b** 正常执行器唯一所有者；P1a 允许由单一最小测试入口调用驱动。紧急安全原语可绕过正常控制路径。
- 不重新设计硬件引脚、供电、MCU、操作系统架构；发现实际硬件冲突或需要改冻结约束时停止并上报，而非自行处理。

## 3. 明确不做

- 不实现 FreeRTOS 任务、控制源仲裁、通信协议、姿态解算、传感器驱动、多外设压力测试和看门狗整套系统。
- 不引入完整 VisionArm App、不复用 `gimbal_control.c`/`gimbal_task.c`、不迁移 USART2 协议。
- 不为成功编译而删除故障检查、限幅或禁止输出路径。
- 不修改/推送旧仓库；新仓库不执行无授权的 push、force-push、历史改写。

## 4. 初始验收标准（编码开始前固定；如需变更须先记录批准）

- 波形周期：20000 µs ±100 µs；稳定态高脉宽：设定值 ±10 µs（须在逻辑分析仪采样分辨率与门限条件允许下判定）。
- 每种稳定工况测量不少于 100 个连续 PWM 周期，记录 sample rate、Logic Threshold、探头和连接、设备型号及原始证据。
- 两路独立限幅、双通道更新、首次使能、主动禁用、故障禁用与恢复不得有未授权输出或异常窄/宽脉冲；输出禁用后的波形停止、软件初始化后观察 GPIO 低电平。
- 复位至软件第一次配置引脚前的高阻/电气状态**不能仅凭逻辑分析仪低电平显示认定被主动驱动为低电平**。
- 必须实际完成受限机械测试才能判 P1a `ACCEPTED`。舵机电源独立、与开发板共地已由用户确认，但仍须在测试现场核对供电能力、电平和机械间隙。

## 5. Gate 判定

- `ACCEPTED`：构建、引脚映射、实测 PWM、默认/异常禁用、限幅、恢复、受限机械测试以及 SHA/证据记录均满足。
- `PARTIAL`：实现已完成部分内容，但缺少任一非可忽略的实测验收证据（必须注明未完成项）。
- `BLOCKED`：必要条件缺失或发现架构/硬件冲突导致无法安全推进。
- `FAILED`：已测试且安全要求或预先设定的验收标准不满足。
