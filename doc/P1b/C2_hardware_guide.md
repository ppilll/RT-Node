# C2 无 SWD 验证步骤

本轮只交付源码、构建和主机测试，**未操作板卡**。用户明确选择本轮不新增 trace 引脚；不占 USART1，无串口输入、RAM mailbox 或 SWD Watch 前提。P1a Case1–3 已报告通过，不要求重做。

## 镜像与授权

所有镜像均由唯一 `Projects/RTnode.uvprojx` / `Target 1` / ARMCC 5.06u7 构建。

| 镜像目录（`evidence/C2/` 下） | 行为 |
|---|---|
| `default/RTnode.hex` | 正式默认固件，P1B_AUTOTEST_ENABLE=0，无 Enable/Apply/测试源链接代码，始终禁止输出。普通 `Projects/RTnode.hex` 已恢复为此镜像。 |
| `case1/RTnode.hex` | 有限中位/小幅变化；约2s预等待，启用后约28s活动窗口，结束关闭，不再运行，除非 MCU 复位。 |
| `case2/RTnode.hex` | 在 step=200 生成正好过期的命令，拒绝该命令并锁存关闭，不恢复。 |
| `case3/RTnode.hex` | 在 step=200 故意额外阻塞40 ticks，恢复执行后立即按迟到锁存关闭，不追赶。该40ms内PWM保持旧目标，本阶段没有独立硬件 watchdog，不声称期间已停。 |
| `case4/RTnode.hex` | 在 step=200 有限注入约3ms执行负载，>=2ms观测预算触发锁存关闭，不恢复。注入循环有固定上限。 |

这些 C2 case 与 P1a 同名 case 不相同。case2–4 通常在启动约6s后停，但不能凭近似停止时刻判断精确任务时间或故障原因。

测试镜像编译须同时有 `P1B_AUTOTEST_ENABLE=1`、`P1B_UNLOADED_ACK=1`、`P1B_TEST_ARM_KEY=0xC2201500UL`；CASE=1..4。该 key 是防误配置标记，不是密码/远程授权。缺任一项、残留生产授权、P1a 测试并开或 trace=1 均编译拒绝。**每次复位测试镜像都会重新开始，因此所有测试镜像仅用于断开舵机信号和舵机供电的环境。** H10/B10 不使用这些自动镜像。

复建（只构建不烧录，先关闭其它 Keil 实例）：

```powershell
./doc/P1b/C2_build.ps1
python doc/P1b/C2_host_test.py
python doc/P1b/C2_verify.py
```

脚本在同一工程上临时变更编译宏，逐个保存镜像，finally 恢复原始工程字节，最后构建默认未授权镜像。不要与其它构建/编辑同时运行；失败时检查日志与工程宏，禁止用旧 HEX 冒充本轮结果。原始日志中的 V6.16 是本机注册标签，Tool Versions/独立 armcc --vsn/MAP 证明实际使用5.06u7，详见交接。

## 人工执行顺序

1. 记录板型、下载器/CH340方式、供电、LA型号/采样率/阈值。断开舵机信号和供电；只将 LA 与 MCU 共地，CH0→PC6，CH1→PC7。使用现有下载方式手动烧录指定目录 HEX，先核对 `hashes.json`；本轮没有自动下载。
2. 先烧录 `default`。捕获上电及复位前后 PC6/PC7，应持续低、无 PWM，持续观察至少35s。低电平本身不能证明 scheduler 正常运行。异常输出立即停止。
3. 烧录 `case1`，从复位前开始捕获至少35s。预等待约2s为低；Enable的首个PWM周期仍为完整低帧，下一自然UEV开始完整1500µs中位。ControlTask 额外同时等待 >=40 ticks / >=40ms DWT 后才允许第一次 Apply，不能 Enable 后立即 Apply。
4. 预期名义阶段如下，每个 step 间隔20 ticks；任务与TIM3不锁相，CCR shadow可能顺延一帧，不用这一帧差声称任务失约。宽度仅作为 PWM 结果验证，**不能代表 ControlTask 周期**。

| 活动 step | 名义时长 | Pan/Tilt（µs） |
|---|---|---|
| 0..199 | 约4s | 1500/1500（包含初始低帧与priming） |
| 200..399 | 约4s | 1450/1500 |
| 400..599 | 约4s | 1550/1500 |
| 600..799 | 约4s | 1500/1500 |
| 800..999 | 约4s | 1500/1450 |
| 1000..1199 | 约4s | 1500/1550 |
| 1200..1399 | 约4s | 1500/1500 |
| step=1400 | 永久关闭 | 不自动重新 Enable |

5. 沿用预设 PWM 标准：周期19900..20100µs，目标脉宽±10µs；各稳定阶段至少100周期。检查首次低帧、中位完整帧、变化一致性和最终低电平。Disable/ForceSafeOutput 可立即截断正在输出的最后一个脉冲，这是强制关断边界，不能要求它等待完整帧。未记录具体测量值不得填PASS。
6. 分别手动烧录 case2、case3、case4，捕获启动、停机及停机后至少10s。检查停后双路持续低，未出现第二次运行。case2拒绝过期命令；case3在故意迟到恢复后关闭；case4因执行超限关闭。它们不用于证明精确故障关断延迟，也不保证能从PWM单独区分故障原因。
7. 测试结束手动烧回 `default` 并核对其哈希，再观察无PWM。记录每次所用镜像、下载时间、复位动作、原始LA工程/CSV路径和实际结果。出现错误时保留证据，不移除断言、不扩大容差、不清除驱动锁存继续跑。

本轮所有这些板上步骤为 NOT_RUN。若测试镜像没有出现预期波形，不能仅凭输出为低宣称通过；可能是启动自检或调度/时钟/驱动关断，需另行定位。

## 时序与资源测量方案（本轮 NOT_RUN）

本轮未分配 GPIO，`P1B_TRACE_ENABLE=1` 明确编译拒绝。将来如补测，须先核对实际开发板原理图/接线，排除全部冻结资源，获得具体引脚或诊断通道批准后再作小范围增量；本交付不假定 PC8/PC9 或 USART1 空闲。

- 唤醒测量：经批准的独立 trace 在每轮入口发上升沿；捕获至少1000连续间隔，最小负载=ControlTask+Idle，保留相同ARMCC优化与固件哈希。仪器候选采样>=10MHz、分辨率<=0.1µs，实际能力必须在试验前记录确认。
- 执行窗口：入口（`entry_cycle`前）置高，`SampleStack`完成后置低，对应本次内部DWT统计窗口，含检查/命令处理/driver API/栈扫描以及其间ISR干扰；不含后续诊断统计写入与xTaskDelayUntil阻塞。marker本身开销须记录。窗口宽度是观测值，不是所有未来负载下WCET保证。
- 试验前固定候选标准：wake间隔19..21ms、窗口<2ms。内部runtime规则为20tick目标、lateness<=1tick、间隔19..21tick、窗口<144000cycles；周期DWT与tick的±2ms一致性检查用于发现异常时基，不能替代外部验收。报告 N/min/avg/max、抖动定义、负载、deadline计数及仪器分辨率，不事后修改阈值。
- 关断时延候选：从可外部标记的“检测到失效/超限”事件到PC6/PC7强制低，先审查并批准<1ms候选，再实际捕获检测marker和PWM。当前没有检测marker，因此该时延为NOT_RUN；40ms迟到注入的等待时间不包含在“检测后时延”内，并须单列。
- 栈余量：ControlTask已内部调用真实 uxTaskGetStackHighWaterMark，记录Control/Idle最小值，单位words，乘4为bytes；但无批准读出通道，真实余量NOT_RUN。主机stub中的180/100是测试输入，不得抄为板上结果。MAP只证明分配与静态RAM预算，不证明栈够用。
- 当前软件保护依赖任务最终重新获得CPU/时基继续运行；完全停Tick、任务永久卡死或scheduler永久停止，需要独立watchdog/硬件保护，属于未实现范围。软件PWM关闭不等于机械制动或断电。

不自动开始P2，不将无负载波形当作H10机械验收。
